## 目录

```
studio/
├── build.mjs          一键出片

    ├── storyboard.json 你写的

    ├── audio/         配音缓存（按文本 hash）

```

## 命令

```bash
cd studio

node build.mjs projects/<名字> --timeline          # 配音 + 时间轴（秒出，先对轴）
node build.mjs projects/<名字> --stills 3,12,24    # 截关键帧审画面
node build.mjs projects/<名字>                     # 全片渲染 + 混音 + 合流

node build.mjs projects/<名字> --rate +12%         # 临时改语速
node build.mjs projects/<名字> --fps 30
```

预览（连续播放）：浏览器打开 `projects/<名字>/index.html`。

## 时间预算（M 系列 Mac，纯 CPU）

| 环节 | 速度 |
|---|---|
| 配音 | 每镜 1–3 秒（有缓存） |
| 渲染 | **约 18 帧/秒** → 60 秒片子约 110 秒 |
| 混音 + 合流 | 5–10 秒 |

所以一条 60 秒的片子，全流程 2–3 分钟。

## 排错

### 渲染卡住 / 帧数不动

**九成是 Chrome 的 profile 锁被上次中断的进程占着。**

```bash
killall -9 "Google Chrome"
rm -rf projects/<名字>/.chrome-profile
```

然后再跑。这个问题在中断过渲染之后几乎必现。

### `The browser is already running for …`

同上，profile 被占。删 profile 或换一个项目名。

### edge-tts 连不上

接口偶发 `connection reset`（实测成功率约 1/3）。`tts.py` 里带 24 次快速重试，正常会自动过。
如果整段退回系统 `say`，音色会明显变差——**检查日志里有没有「退回 say」**，有的话重跑一次。

### 视频素材自带字幕，和字幕打架

用 `zoom` 放大裁掉底部：

```json
{"type":"video","params":{"src":"assets/x.mp4","zoom":1.3}}
```

或者换一段没有烧录字幕的素材。

### 图片比例不对 / 关键内容被裁

`image` 用 `object-fit: cover`，会裁边。重要内容别放边上，或者先用工具裁好再放进来。

### 字幕闪一下

句子太碎、镜头太短。合并短句（但**不能改字**——把两句并进一个镜头）。

### `say` 念英文词怪

在词后加逗号让它停顿：「transform，这个属性」。**不要改词。**

### 时间轴比预期长

单镜超过 9 秒就会拖。`--timeline` 输出里每镜都有时长，超了就拆。

## 换成 MiniMax 配音（中文最像真人）

一句话：**edge-tts 免费但天花板明显；MiniMax 是"像人"的那一档**，同一条 3 分钟片子约两毛钱。

### 拿 key

1. `platform.minimaxi.com` 注册，控制台是**积分制**
2. **账户管理 → 账户信息 → 基本信息** → Group ID（19 位数字）
3. **账户管理 → 接口密钥 → 创建** → 弹窗里**当场复制**（关掉就看不到，只能重建）
4. **「积分余额」卡片 → 充值积分**（10 元够跑 40 条 3 分钟片）

> **GroupId 可以留空**：新版 `t2a_v2` 不传也能调。真报错再去填。

写进 `studio/.env`（模板见 `.env.example`）：

```
MINIMAX_API_KEY=sk-api-...
MINIMAX_GROUP_ID=
MINIMAX_TTS_MODEL=speech-02-hd
MINIMAX_VOICE_ID=male-qn-daxuesheng
```

**不要让用户把 key 贴在聊天里**——让他自己写进 `.env`，你只读文件。

### 选音色：先 A/B，再全片

327 个系统音色，别猜。拉列表：

```bash
curl -s -X POST "https://api.minimaxi.com/v1/get_voice" \
  -H "Authorization: Bearer $MINIMAX_API_KEY" -H "Content-Type: application/json" \
  -d '{"voice_type":"system"}'
```

按 `voice_name` 过滤（男 / 青年 / 主播）。实测适合「科普口播」的：

| voice_id | 名字 | 特点 |
|---|---|---|
| `male-qn-daxuesheng` | 青年大学生 | **最像"学长给你讲"**，亲切、不油（默认） |
| `Chinese (Mandarin)_Unrestrained_Young_Man` | 不羁青年 | 最"调侃"，讲反直觉结论很搭 |
| `Chinese (Mandarin)_Radio_Host` | 电台男主播 | 最像专业科普播主，稳 |
| `male-qn-qingse` | 青涩青年 | 偏嫩，说段子不违和 |
| `male-qn-jingying` | 精英青年 | 冷静清晰，幽默感最弱 |

**流程：先出 5 人 A/B 让用户挑，再全片重录。** 脚本：

```bash
../.venv/bin/python ab-voices.py      # 每个音色自报编号 + 念同一段，拼成一条
```

### 切换

```json
"meta": { "engine": "minimax", "voice_id": "male-qn-daxuesheng", "rate": "-5%" }
```

- `rate` 会自动换算成 `speed`（`+8%` → 1.08，`-5%` → 0.95）
- **MiniMax 比 edge 快约 13%**：要保持原有的听感节奏，把 rate 调到 `-5%` 左右

### 三个必踩的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **RPM 限流** | `status_code 1002 rate limit exceeded`，然后**全部静默回退 edge** | `tts.py` 已加：每条间隔 0.8s + 命中 1002 时退避重试 6 次 |
| **emotion 不被支持** | `invalid params: voice_setting emotion` | 只有显式指定才发；被拒自动去掉重试 |
| **缓存串味** | 回退产出的 edge 音频被存成 minimax 的缓存，下次直接复用 | 缓存 json 里记 `src`，来源对不上就重做；缓存 key 带 engine+voice_id |

**排错口诀**：日志里出现 `edge` 而你要的是 minimax，就是上面三个之一。先看 stderr 有没有 `minimax 返回异常`。

## 语速与停顿：不要滥用断点标记

`tts.py` 支持在稿子里用 `｜`（0.08s）/`｜｜`（0.22s）标停顿。**但默认不要用。**

### 为什么

TTS 是按"句子"合成的。你在句中插一个 `｜`，等于把它**切成两句话**分别合成，
每个片段都会带自己的**句尾降调 + 句尾静音**，拼起来就是：

> 半句话（降调）…停… 半句话（降调）

听起来"一顿一顿的"，而且**总时长会暴涨**：实测 40 处标记，全片从 176 秒涨到 249 秒（+41%）。

### 什么时候才用

- 全片**不超过 5 处**，只放在真正需要"等一下"的地方（一个梗之前、一个结论之前）
- 不要放在普通的从句边界——那里的停顿交给标点（逗号、句号、破折号）就够了

### 更安全的三个旋钮

| 想要 | 调什么 | 量级 |
|---|---|---|
| 整体更快 | `meta.rate` | `+8%` → `+12%`（约快 5%） |
| 句间更紧 | `meta.hold` | `0.15` → `0.05` |
| 句尾不拖 | `tts.py` 的 `trim_tail(keep=)` | `0.30` → `0.15` |

**先调这三个，再考虑断点。** 多数"拖"是三者的叠加，不是断点的问题。

### 自检

渲之前先看 `--timeline` 的总时长：
`字数 ÷ 5.5 ≈ 秒数`（中文口播的正常语速）。如果实际时长比这个多 20% 以上，
就是停顿太多，回去查 `hold`、`trim_tail`、断点标记。
