# 07 · 并行工作流

长片（20 镜以上）别串行做。按下面的 DAG 拆成互不干扰的任务，多 agent 并行。

---

## 为什么能并行

整条流水线只有两处是**全局串行**的：

1. **导演**（要定母题和运动语言，所有人依赖它）
2. **最终渲染**（一个 storyboard 一次渲完）

其余全是**按镜头切片的**，互不依赖：取素材、写分镜、截帧自查。

---

## DAG

```
D1 导演 ──▶ design.md / shots.md
                  │
      ┌───────────┼───────────┐
      ▼           ▼           ▼
   A1 素材组   A2 素材组   A3 素材组      ← 并行：每组负责一段镜头
      │           │           │
      └───────────┼───────────┘
                  ▼
      ┌───────────┼───────────┐
      ▼           ▼           ▼
   S1 分镜组   S2 分镜组   S3 分镜组      ← 并行：各写 chunks/N.json
      │           │           │
      └───────────┼───────────┘
                  ▼
            M 合并 merge.mjs
                  ▼
            R 渲染（单路）
                  ▼
            Q 质检 / 交付
```

---

## 产物契约（并行 agent 之间只通过这些文件通信）

| 阶段 | 产物 | 谁写 | 谁读 | 验收 |
|---|---|---|---|---|
| D | `design.md`、`shots.md` | 导演 | 所有人 | 五个决定都写了；母题出现 ≥3 次 |
| A | `assets/*.jpg`、`assets/manifest.json` | 素材组 | 分镜组 | 每张都肉眼确认过；有署名 |
| S | `chunks/<序号>-<段名>.json` | 分镜组 | merge | 每镜类型/参数齐全 |
| M | `storyboard.json` | 合并 | 渲染 | 镜头顺序正确、id 不重复 |
| R | `out/<slug>.mp4` | 渲染 | 质检 | 1080×1920 / 有声 |

**写作用域**：一个 agent 只写自己的 `chunks/N-*.json` 和 `assets/` 里自己那批文件。
**不要**让两个 agent 同时改 `storyboard.json`。

---

## A 阶段：素材组怎么分工

按 `shots.md` 里的镜头段落分，而不是按素材类型分。

```bash
# A1 负责第 1–10 镜
node fetch-batch.mjs /tmp/a1.json projects/xx/assets
# A2 负责第 11–20 镜，同时跑
node fetch-batch.mjs /tmp/a2.json projects/xx/assets
```

注意：

- **文件名必须带段号前缀**（`a1_court_1.jpg`），否则并行会互相覆盖
- Wikimedia 有 **RPM 限流**（HTTP 429），每条之间 `DELAY=2500`
- 搜 3 次没有合适素材 → 转 `gen-image.mjs` 生成，**不要硬凑**

---

## S 阶段：分镜组怎么分工

每个 agent 拿 `shots.md` 里的一段，输出一个 chunk：

```json
// chunks/2-中段.json
{
  "scenes": [
    { "id": "s11", "type": "image", "say": "…", "params": { "srcs": ["…"], "aside": "…" } }
  ]
}
```

- `id` 按全局序号编，**不要各自从 s1 开始**
- 只写自己那段，不要动别人的文件
- `say` 和 `script.md` 一字不差（断点 `｜` 除外）

---

## 合并

```bash
node merge.mjs projects/xx
```

按文件名排序拼接。约定：

```
chunks/
├── 0-meta.json      可选，覆盖 meta（分辨率/主题/音色）
├── 1-开头.json      scenes[0..9]
├── 2-中段.json      scenes[10..19]
└── 3-收尾.json      scenes[20..]
```

---

## 渲染能不能并行？

**默认不并行**。渲染是 CPU 密集的，一台机器上开两路只会互相抢核，总时长不变。

真要并行，唯一有效的切法是**按时间段切**：

```bash
# 每段渲一个独立 mp4，参数必须完全一致
node build.mjs projects/xx --range 0 90      # 0–90 秒
node build.mjs projects/xx --range 90 180
ffmpeg -f concat -i list.txt -c copy out.mp4
```

代价是要处理接缝（字幕/动画在切点会被截断），一般不值得。**别为了并行而并行。**

---

## 并行 agent 的三种典型冲突

| 冲突 | 现象 | 预防 |
|---|---|---|
| 抢同一个文件名 | 后写的覆盖先写的 | 文件名加段号前缀 |
| 各自从 s1 编号 | 合并后 id 重复 | 导演在 shots.md 里预先分配全局镜号 |
| 视觉各画各的 | 拼起来风格突变 | `design.md` 先定色/字/运动，**所有分镜 agent 必须先读它** |

---

## 一个反直觉的建议

并行只对**素材和分镜**有意义，对**创意**没有意义。

导演这一步**千万不要拆**。三个人各想一个母题，最后一定是四不像。
宁可导演慢一点、想透，再让十路 agent 去执行。
