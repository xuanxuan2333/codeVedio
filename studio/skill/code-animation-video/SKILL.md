# 科普动画视频

用户给一段文案，你出一条视频。

**文案是他的，画面是你的。**

---

## 0. 四条底线

1. **几乎不改文案。** 只改三类：严重语病、错别字/识别错、事实错误。
   口头禅（诶、那个、就是说、然后呢）、口语、重复、语序、语气——**一律保留**。
   你是在配画面和排版，不是重写他的稿子。
2. **一句话一个镜头，画面从这句开头就出现。**
   括号写在句尾，但它描述的画面要在**这句开口的同时**就在动，不是说完再上图。
3. **先审画面，再渲全片。** `--stills` 没过，不许渲全片。
4. **先当导演，再当排版。** 母题、色光、运动语言定下来之前，不写分镜——否则必是 PPT。
5. **语速要有快慢。** 全片同一个速度 = 没有重点。按句意给每镜标 `rate`，见 `08-语音表演.md`。
6. **视觉要有规矩。** 三个颜色、一个图片来源、层级分明；渐变从主题前景色起，不许写死白色。见 `09-视觉规范.md`。


  （这是这套流水线的官方仓库，studio/ 和 skill 都在里面）

依赖：Node 20+、`.venv`（ffmpeg + edge-tts）、本机 Chrome。缺了自己装，别停。

**配音两档**：
- 默认 `edge-tts`（免费、够用，但"像 AI"）
- 要"像人"就切 MiniMax（约 0.2 元/条 3 分钟片）：`meta.engine = "minimax"` + `voice_id`
  取 key、选音色、避坑见 `references/05-出片与排错.md`「换成 MiniMax 配音」一节。
  **换音色先出 5 人 A/B 让用户挑，别直接全片重录。**

## 2. 流程（七步，含导演与并行）

| 步 | 做什么 | 产出 | 停下 |
|---|---|---|---|
| 0 | **校对** | 只改语病/错别字/事实错误；逐条列出 | — |
| 1 | **导演** | `design.md` + `shots.md`：一句话主张、母题、色/光、运动语言、逐镜设计 | ⏸ 给用户看方案 |
| 2 | **素材**（可并行 N 路） | `assets/*` + 每张都肉眼确认 | — |
| 3 | **分镜**（可并行 N 路） | `chunks/N-段名.json`；每镜按句意标 `rate` / `hold` | — |
| 4 | **合并 + 对轴** | `node merge.mjs` → `--timeline` | — |
| 5 | **审画面** | `--stills` 看 5 个以上时刻 | ⏸ 自己过三问 |
| 6 | **渲染** | `out/<slug>.mp4` | — |
| 7 | **质检交付** | 视频 + 校对清单 + 判断说明 | ⏸ 交付 |

**第 1 步不许跳过。** 没有 `design.md` 就开工，结果一定是 PPT：
一句一屏、左标题右列表、每屏都在列点。

**长片（20 镜以上）走并行**：素材和分镜按镜头段拆给多个 agent，
导演和渲染**不拆**。分工与产物契约见 `references/07-并行工作流.md`。

## 3. 校对（第 0 步，最容易做过头）

**只改这三类，其余一律不动：**

| 只改 | 判定 | 例子 |
|---|---|---|
| 严重语病 | 读不通、有歧义、指代不清 | 「这个是因为由于它」→「这是因为」 |
| 错别字 / 识别错 | 打错字、语音转文字同音字 | 「以经」→「已经」 |
| 事实错误 | 年份、人名、因果与可查来源冲突 | 改完必须告诉用户，**不许默默改** |

**可以顺手做的（不算改写）：** 补标点（TTS 要断句）、英文数字排版统一（`AI` vs `A.I.`）。

**明确不改：** 口头禅、口语化表达、重复啰嗦、语序断句、语气词、方言、以及"你觉得不够专业"的表达。

细节与交付话术：`references/01-校对.md`

---

## 4. 拆镜（第 3 步）

- **一句一镜。** 一句话配一个画面。一句太长不是改句子，是**拆成两个镜头**（画面换一次）。
- **括号优先。** 用户写了 `（画面：…）` 就照做；描述不清时按 `references/04-编译规则.md` 的决策树补全，并在交付时说一句"这里我按 X 理解"。
- **没写括号就自动配**：人 → `person`，公司 → `brand`，枚举 → `bullets`，数字 → `stat`，差异 → `compare`，流程 → `flow`。
- **括号要图，就给 3–5 张。** 一张图撑整句会显得死板；`image` 支持 `srcs` 数组，按句长自动排（每张约 2.4 秒）。取图加 `--count 3`。
- **一句话里塞了三件事，一个画面接不住**——那就拆镜，别硬塞。

## 5. 写 storyboard.json（第 3 步）

```json
{
  "meta": {"title": "标题", "slug": "英文短名", "voice": "zh-CN-YunxiNeural",
           "rate": "+8%", "fps": 30, "hold": 0.4},
  "scenes": [
    {"id": "s1", "type": "title",  "say": "这句的口播，原样照抄", "params": {"title": "…", "sub": "…"}},
    {"id": "s2", "type": "bullets","say": "…", "params": {"title": "…", "items": ["…", "…"]}}
  ]
}
```

- `say` 是**配音文本**，必须和校对后的原文一字不差（标点除外）。
- 每个镜头都可以加 `params.aside`（言外之意），渲染成右下角一行蓝字，见 `references/03-镜头库.md` 第 0 节。
- 镜头时长不用填，由配音长度自动算；`hold` 是每镜尾部留白。
- 15 种镜头的参数：`references/03-镜头库.md`

## 6. 出片（第 4–6 步）

```bash
cd studio
node build.mjs projects/<名字> --timeline        # 先对轴
node build.mjs projects/<名字> --stills 3,12,24  # 再审画面
node build.mjs projects/<名字>                   # 最后全片
```

- 语速临时改：`--rate +12%`
- 审画面用 `stills/` 里的 PNG，**必须真的看图**，不能只看日志。
- 排错（Chrome 锁、edge-tts 连不上、字幕打架）：`references/05-出片与排错.md`

---

## 7. 自检（第 5、7 步）

遮住字幕和小字，任取五镜，问三句：**这是什么？它在干什么？我看明白了什么？** 答得含糊就是没做好。

其余硬指标见 `references/06-质检.md`。

---

## 8. 交付（第 7 步）

```
成片：projects/<名字>/out/<slug>.mp4（X 秒）
封面：out/poster.png

校对：未改动 / N 处（逐条列）
画面：我做了哪几处判断（比如"「寒冬」没有具体素材，用了金句镜头"）
没做到的：……
```

**「未改动」三个字必须写清楚。** 用户看到这四个字，才知道你没在背后重写他。
