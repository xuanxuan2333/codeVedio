你在 B 站看到的那些「用动画讲清一个原理」的片子，基本都是程序化渲染出来的： 写代码描述图形和时间轴，渲染器把它变成一帧帧画面。 这里用同一个镜头（平移 → 旋转 → 缩放 → 变色）在主流工具里各写一遍，并给出真实产物、优劣和选型建议。

01先给结论

三句话，看完可以关页面去干活。

这类视频的本质不是「视频」，是程序化图形 + 时间轴。
AI 不生成像素，AI 生成代码，代码再被渲染器逐帧画出来。

这正是它和 Sora / 可灵那类「文生视频」最根本的区别：前者是确定性渲染——同一份代码永远出同一帧； 后者是概率采样——每次都不一样，文字必糊、几何必漂。 讲原理要精确，只能走前者。

讲前端 / 浏览器 / 代码 / 系统

03真实产物：同一个镜头，三种渲染

同一份镜头脚本（平移 1.5s → 旋转 1s → 缩放 1s → 变色 + 出字 0.9s）， 分别在 Manim、Remotion、裸 HTML+Puppeteer 里实现并渲染。都是 1280×720 / 30fps / 5 秒。
注意看差异：Manim 的动画是「对象的属性变迁」，Remotion 是「帧号查表」，纯 HTML 是「我按时钟算样式」。 最终的画面可以做到几乎一样，但写代码时脑子里想的事情完全不同。

三段视频会从头同时播放，方便对比节奏和缓动差异
Manim CE 0.22python · 4.5s
Remotion 4.0react · 5.0s
HTML + Puppeteerjs · 5.0s

为什么只实拍了这三个？ 另外几个要么需要 Node ≥ 22（HyperFrames 会直接拒绝启动），要么需要先搭一套 Vite / 浏览器项目脚手架（Motion Canvas、Revideo）。 Motion Canvas 和 Revideo 的代码在第 05 节照写不误——它们的 API 是清楚的，只是本机没跑通渲染链。 能跑的都跑了，没跑的会明说。

04八个工具，逐个说优劣

不吹不黑。每条都尽量具体到「你会踩到什么」。

01

Manim CE

Python 数学动画的默认答案，3Blue1Brown 的开源引擎

优势

  • 公式排版是原生能力，LaTeX 直接写成对象，这是其他工具追不上的
  • 几何变换、坐标系、函数图像有大量现成积木（Axes、Transform、Mobject）
  • 社区语料最厚，LLM 训练数据里 Manim 代码非常多，AI 写它的命中率最高
  • 同一个对象可以「变形」成另一个对象，这是它的杀手锏

短板

  • 依赖重：cairo、pango、LaTeX，装环境就能劝退一半人（本机是 conda 装的）
  • 没有实时预览，改一行等一次渲染；分镜级调试很慢
  • 排版是手工坐标，文字多了容易叠在一起，AI 尤其容易犯这个错
  • 做网页 UI、代码高亮、复杂图表要自己造轮子
✓ 本机已渲染MIT 选它：你要讲的是数学、物理、算法，公式是主角。
02

ManimGL

3b1b 本人天天在用的那一版，实时、但更野

优势

  • OpenGL 实时预览，改代码立刻能看到，调动画手感最好
  • 3b1b 视频里的效果都能复现（他用的就是这个）
  • 性能好，长片段渲染比 CE 快

短板

  • API 不稳定，版本之间会破坏性变更，网上教程经常对不上
  • 文档远不如社区版，出问题基本靠读源码
  • 需要图形界面，服务器上跑不了（无头渲染要额外折腾）
未渲染MIT 选它：你已经是 Manim 熟手，且需要实时调手感。
03

Motion Canvas

为「矢量图解」而生的编辑器，生成器语法的代表

优势

  • 带可视化编辑器：拖时间轴、实时看画面，调分镜比 Manim 舒服太多
  • yield* 生成器让「等这个动画播完再播下一个」写起来像同步代码
  • 天生适合画流程图、示意图、架构图，配配音做知识类内容很顺
  • MIT，纯前端栈，不用担心许可证

短板

  • 默认输出是图片序列，要自己再合视频（官方 FFmpeg exporter 比较新）
  • 生态小，LLM 见过它的代码远少于 Manim / React，AI 更容易写错 API
  • 没有公式排版能力，数学内容要绕路
  • 上云批量渲染没有现成方案，得自己搭
未渲染 · 需项目脚手架MIT 选它：你要做图解型内容，且愿意在编辑器里手工调。
04

Remotion

React 组件即视频，工程化程度最高的一档

优势

  • 「帧号 → 画面」的纯函数模型，确定性极强，天然可测试、可复现
  • React 生态直接复用：任何网页组件、图表库、字体都能塞进画面
  • 官方支持 AWS Lambda 分布式渲染，几百条视频可以并行出
  • 官方出了 Agent Skills（npx skills add remotion-dev/skills），AI 驱动有正路

短板

  • 许可证是坑：免费仅限个人 / 非营利 / ≤3 人的公司，超过要买商用授权
  • 要懂 React + 构建工具，门槛比「写个 HTML」高
  • 没有内建的矢量图形体系，画图得靠 SVG / div 自己拼
  • 初次渲染要下载 Chrome Headless Shell，国内网络容易卡住（可用 --browser-executable 指向本机 Chrome）
✓ 本机已渲染商用需授权 选它：你要做系列化、批量、团队协作的产品级视频流水线。
05

Revideo

Motion Canvas 的「服务端化」分支，渲染 API 可自托管

优势

  • MIT + 可自托管，没有 Remotion 那种人数限制
  • 一个 renderVideo() 就能把项目渲成 mp4，适合包成后端服务
  • 支持把一次渲染拆到多个 worker，规模化比 Motion Canvas 好
  • README 明说「场景就是普通 TypeScript，Claude / Codex 能直接写」

短板

  • 生态比 Motion Canvas 还小，文档和示例少
  • 没有编辑器，纯代码，调版式靠反复渲染
  • 版本迭代快，API 有变动风险
未渲染MIT 选它：你要把「生成视频」做成一个能调用的接口。
06

HyperFrames

HeyGen 开源：视频源文件就是纯 HTML，为 Agent 而生

优势

  • 没有新框架要学：HTML + CSS + data-* 时间属性就是全部
  • 官方 21 个 Agent Skills + Claude Code 插件，是这批工具里对 AI 最友好的
  • 确定性渲染写进了规范（禁用真实时钟、未播种随机），同输入同输出
  • Apache-2.0，还能上 AWS Lambda / Cloud Run 渲染

短板

  • 要求 Node ≥ 22，本机 21.7 直接被拒绝启动（这次就卡在这）
  • 很新，社区案例少，踩坑只能看文档
  • 复杂动画仍要自己写 GSAP / CSS，没有 Manim 那种「对象变形」
  • 设计上偏向「页面即视频」，长叙事的分镜管理要靠自己组织
未渲染 · 本机 Node 21Apache-2.0 选它：你讲的是网页技术，且想让 AI 直接写 HTML 出片。
07

vawe

最激进的一派：你写的页面就是电影，不需要构建

优势

  • 用虚拟时钟替换 Date、定时器、rAF、Math.random，普通网页直接变确定性视频
  • 不需要改写成某种 DSL，现有页面 CSS 动画原样跑
  • Apache-2.0，没有人数限制

短板

  • 生态极小，只有本地渲染，没有云渲染
  • 没有时间轴编辑器，复杂编排全靠手写
  • 依赖「页面本身写得好」，页面写得乱，片子就乱
未渲染Apache-2.0 选它：你已经有一堆网页素材，只想合成为视频。
08

裸 HTML + Puppeteer

不到 60 行，最透明、最容易让 AI 接管的那条路

优势

  • 没有黑盒：seek(t) → 截图 → 管道给 ffmpeg，全程看得见
  • 零框架依赖，出问题一定是你的问题，一定能定位
  • AI 最好写——HTML/CSS/JS 是训练数据里最多的东西
  • 本项目 70 秒正片就是这么渲的：2123 帧，124 秒

短板

  • 分镜管理、时间轴、并行渲染、音频对齐，全要自己写
  • 性能靠调：PNG 截图 327ms/帧，换 JPEG 后 56ms/帧，差 6 倍
  • 没有编辑器，改一版要看一版
  • 团队协作时缺少约定，容易各写各的
✓ 本机已渲染自己的代码 选它：你想先跑通闭环，或者要做高度定制的东西。

06怎么选：三个问题定下来

    
按顺序问自己，第一个「是」就是答案。

    

      

        
① 内容里有大量公式 / 坐标 / 函数图像？

        
Manim

        
别的工具做公式要自己拼 SVG，属于逆天而行

      

      

        
② 讲的是网页、浏览器、前端、代码本身？

        
HTML 系

        
HyperFrames（Node≥22）/ vawe / 裸 Puppeteer，任选

      

      

        
③ 要做系列、批量、多人协作、上云？

        
Remotion

        
先确认公司人数，超过 3 人要买商用授权

      

      

        
④ 都不是，只想先跑通一条闭环？

        
裸 Puppeteer

        
60 行代码，两小时能出第一条片子

      

    


    

      
一个反直觉的建议：

      

        如果你打算让 AI 来批量生产，不要选自由度最高的工具，要选约束最强的。
        Manim 的自由度是「什么都能画」，所以 AI 什么都敢画，翻车率也最高；
        HyperFrames / 裸 HTML 的自由度是「一个 HTML 页面」，AI 反而稳。
        真正的成品率来自场景库 + 固定栅格 + 渲染后自检，不是来自工具本身。
      

    

  






  

    
07AI 接入：谁能被 Agent 直接驱动

    
2026 年的现实：不是「AI 能不能写动画」，而是「哪个工具给 AI 留了门」。

    

      

        
工具官方 AI 支持实际怎么用

        
          
Remotion官方 Agent Skills
              npx skills add remotion-dev/skills，让 Claude Code 按规范写组件

          
HyperFrames21 个 skills + 插件
              Claude Code 插件直接写 HTML 组合，官方提供 router skill 分发

          
RevideoREADME 明确支持
              「a scene is plain TypeScript」——模型直接写场景文件

          
Manim社区生态
              manim-mcp（MCP 工具）、manimkit（语料 + linter + render-and-look）、3brown1blue（27 条规则文件）

          
Motion Canvas未见官方
              语言模型懂 TS，但语料少，API 容易编错，需要人兜底

          
vaweCLI + skills
              把已有页面丢给 CLI 渲染，AI 只需要改页面

          
裸 Puppeteer天然适合
              没有 API 要记，AI 只需要写 HTML + 一个 seek(t)

        
      

    


    

      

        所有能用的方案，都长同一个样：
        生成代码 → 真渲染 → 看画面 → 发现错了 → 改 → 再渲染。
        这一步叫 render-and-look。没有它，模型就是在闭着眼睛画图——
        文字叠在一起、元素飞出画布、颜色撞成一团，它自己完全不知道。
