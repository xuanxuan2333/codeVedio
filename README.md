## 0.1 三十秒看懂

```
你写的                        你得到的
─────────────────────────────────────────────
一句口播。                    ┌──────────────┐
（画面：片名卡 · 标题…）  ──▶  │  storyboard  │ ──▶ 配音 → 时间轴 → 逐帧渲染 → mp4
一句口播。                    │    .json     │
（画面：左右对比 · A vs B）     └──────────────┘
```

- **入口**：`projects/<名字>/script.md`（人写的，带括号）
- **中间产物**：`storyboard.json`（agent 把括号翻译成结构化的镜头）
- **出口**：`projects/<名字>/out/<slug>.mp4`

一条命令：

```bash
cd studio && node build.mjs projects/demo
```

核心事实：**画面是代码画的，不是 AI 生成的像素**。所以它确定性、可复现、文字永远清晰、几何永远正确 —— 这正是「讲原理」需要的。

## 1. 六条硬规矩（先读，比工具重要）

这几条决定了片子是「讲解」还是「配图」。违反任何一条，后面的渲染再漂亮也是废片。

### 1.1 配图不是讲解

一个真实的失败案例：讲蛋白质折叠，画面是一串星点连成的折线；字幕说"第 6 颗换了颜色，形状就变了"，折线换了个卷法、变了个颜色。
颜色、字体、节奏都对，但观众**从头到尾没见过蛋白质是个什么东西**。

检验方法：**把那串图形换到别的文案里，如果照样成立，它就是配图，不是讲解。**

### 1.2 一镜一件事

一屏只让观众看一件事。想同时说三件事，就是三个镜头。
旁白 6 秒 ≈ 一屏的容量；超过 8 秒的镜头，要么拆开，要么画面里得有第二段动作。

### 1.3 屏上的东西，观众得认得

"工作记忆""双通道""认知负荷"——这些词没有形象。要么换成观众生活里见过的东西（一张桌子、一趟地铁、一个水桶），要么**这一镜就别配图，只上字**。
抽象词硬配一张抽象图，是最常见的翻车方式。

### 1.4 动词要真的发生

旁白说"减半"，屏幕上就真的少一半；说"跳过了这一步"，那一步就在画面上被划掉。
**说了变化，画面就得动**；没有变化的镜头，观众会走神。

### 1.5 先例子，后道理

前 3–10 秒给一个具体到能看见的东西，再给定义和结论。
所以 `script.md` 的第二镜通常是 `stat` 或 `compare`，`bullets` 讲道理放在后面。

### 1.6 该停就停

提问、命名、下结论、引出处——这四类句子**不配新画面**。
参考片里大约每五句有一句是这样。全靠画面填满，观众会累。

> 判断标准：**这一句有东西在动吗？** 没有就别画。

## 2. 输入格式

`script.md` 就是普通的中文稿子，一行口播、一行括号：

```markdown
同样一个知识点，做成动画，比写成文字，更容易被记住。
（画面：片名卡 · 主标题「为什么动画更好懂」，副标题「双通道编码，一次讲清」）

这不是感觉。同一份内容，配上画面和讲解，回忆的准确率大概能翻一倍。
（画面：大数字 2 倍，下面一行说明「画面 + 讲解 vs 只有文字」）
```

规则：

| 规则 | 说明 |
|---|---|
| **一行口播 = 一次配音** | 逗号句号都照读，TTS 自己断句 |
| **一个空行 = 一个镜头** | 口播和括号成对出现，顺序不能乱 |
| **括号里写"意图"，不写代码** | 写"左右对比"，不用写 `"type":"compare"` |
| **一句一屏最好** | 超过两句就拆成两个镜头，画面才跟得上 |
| **旁白里的每个名词，屏上要能找到** | 找不到就改稿，不要硬画 |

括号里可以写得很随意（自然语言），因为**它要过一遍 agent 的翻译**，不是给机器直接解析的。

### 2.1 括号写在句尾，画面出现在句首

这是最容易搞错的一条。

括号通常**写在句子的末尾**，但它描述的画面要在**这句话开口的同时**就出来——不是等你说完这一句才上图。

```
声音： │────── 这句话 ──────│
画面： │── 就位 ────────────│
       ↑ 开口的同一刻，画面已经在动（0.5 秒内完全就位）
```

原因很直白：观众是"先看见，再听懂"。等一句话说完才把图放上去，图和话就错开了半拍，看着像 PPT 翻页。

**所以：一句一镜。** 一句话配一个画面，画面从这句的第一个字开始。段落里如果只有最后一句写了括号、前面几句也要画面，就把这段拆成几个镜头，**括号跟着它描述的那一句走**。

反例（一句里塞了三件事，一个画面接不住）：

> 最早是 1956 年达特茅斯会议，麦卡锡提出了这个词，然后经历了好几次寒冬（画面：大数字 1956）

观众听到「寒冬」的时候，屏上还停着 1956——画面比声音慢了一个信息点。

正例（拆成两镜，各自从自己的句首开始）：

> 嗯，最早是 1956 年达特茅斯会议。（画面：大数字 1956）
>
> 然后是好几次寒冬，钱烧完了就没人管了。（画面：金句「钱烧完了，就没人管了」）

**默认行为**：每个镜头的画面动画都从该镜的 `t=0` 开始（也就是这句配音的开始），在 0.3–0.6 秒内完成入场。镜头时长由这句的配音长度决定，不用你算。

## 2.5 输入契约（最重要的约定）

用户丢过来的稿子，可能是口语稿、带口头禅、甚至是语音转文字的结果。

**默认策略：逐字保留。** 你的工作是配画面和排版，不是重写他的稿子。改得越多，片子越不像他本人在讲。

### 2.5.1 校对规则：只动三类

**只改这三类，其余一律不动。**

| 只改这三类 | 判定标准 | 例子 |
|---|---|---|
| **严重语病** | 读不通、有歧义、指代不清，观众会卡住 | 「这个是因为由于它的原因」→「这是因为」 |
| **错别字 / 识别错** | 明显打错字，或语音转文字的同音字 | 「以经」→「已经」，「在座实验」→「在做实验」 |
| **事实错误** | 与公认事实冲突，或与可查来源不符 | 年份写错、人名张冠李戴、因果颠倒 |

**明确不改**（这些是风格，不是错误）：

- 口头禅：「那个」「就是说」「诶」「然后呢」「你懂吧」
- 口语化表达：「钱烧完了就没人管了」「这玩意儿」
- 重复、啰嗦、绕：「然后呢然后呢」
- 语序、断句习惯、句子长短
- 语气词、个人腔调、方言用法
- **你觉得「不够专业」「不够高级」的表达**

如果你忍不住想改一句「说得更好」，那就是不该改。

### 2.5.2 三个例外

**① 标点可以补。**
TTS 靠标点断句。一段话一个标点都没有，会念成一口气。补标点不改变用词，不算改写。

> 补之前：「今天聊聊AI的方法它其实分三步」
> 补之后：「今天聊聊 AI 的方法。它其实分三步。」——**一个字没动**，只是断开。

**② 英文和数字的排法可以统一。**
`AI` / `A.I.`、`2012` / `二零一二`，统一成一种写法，方便 TTS 念对、字幕好看。这属于排版。

**③ 事实错误要改，而且必须告诉用户。**
查证后改掉，并在交付时单独列出来：「原稿说 X，实际是 Y，已改，来源是 …」。
**不许默默改**——这可能是他故意说的，也可能是我们查错了。

### 2.5.3 不要为了切镜头而改稿

一句话太长，正常的做法是**把它拆成两个镜头**（画面换一次，句子不动），而不是把句子改短。

只有一种情况需要动文字：**这句话画不出来**（全是抽象词、没有主体、没有动作）。这时候的选择顺序是：

1. 不配画面，直接上字（`quote` / `title`）
2. 换个说法配画面（**只改这一句**，其余不动）
3. 都不行，才回来问用户

### 2.5.4 交付时怎么说

把改动逐条列出，**一条都没有也要写**：

> 校对：未改动（原文没有语病和错别字）。

或

> 校对：3 处——「以经」→「已经」；「2012 年」年份对，但 AlexNet 是 2012 年 10 月发布，原稿写「2012 年出来」可以不改；「三次寒冬」按主流说法是两次起落，已改为「几次寒冬」。

**改动清单是信任的基础。** 用户看到「未改动」，才知道你没在背后重写他。

### 2.5.5 括号优先

稿子里的 `（画面：…）` 是**用户指定的画面**，优先级最高：
- 照做，不要自作主张换掉
- 括号里的描述不清楚时，按第 4 节决策树补全，并在交付说明里写一句"这里我按 X 理解"
- 括号里要求的东西做不到（比如要一段不存在的素材），**说明原因并给替代方案**，不要假装做了
- **画面从这句开头就出现**（见 2.1），不要理解成"说完这句再上图"；一句话里有多个信息点，就拆镜头，别硬塞

### 2.5.6 没写括号时，自动配图

按这个优先级，从上往下第一个能成立的就用：

| 稿子里提到 | 自动用 | 说明 |
|---|---|---|
| 一个**人** | `person` | 去 Commons 找照片 → **亲眼确认是本人** → 用；确认不了用文字卡 |
| 一个**公司 / 产品** | `brand` | 默认用品牌文字卡（配色 + 字号），**不抓 logo** |
| **"三点""几个方面"** 这类枚举 | `bullets` | 用户说了几点就放几条，序号自动 |
| **一个数字 / 年份 / 比例** | `stat` | 数字要真，没出处标「示意」 |
| **两种东西的差异** | `compare` | 左右分栏 |
| **先后 / 流程 / 因果** | `flow` | 3–5 步 |
| **有现成素材**（用户给了图片/视频） | `image` / `video` | 优先用用户的 |
| 都不成立 | `quote` 或 `title` | 上字，不硬画 |

**硬约束：宁可没有图，也不要错图。** 一张错的人脸，比一张干净的文字卡伤害大得多。

## 3. 镜头类型库（12 种）

所有镜头都是「进入动画 → 停留 → 淡出」，时长由配音决定，不用你算。

### 3.1 `title` · 片名卡
用于开场、结尾、章节标题。

| 参数 | 说明 |
|---|---|
| `kicker` | 左上角小字，英文大写最好看，可空 |
| `title` | 主标题，建议 ≤ 12 字 |
| `sub` | 副标题，一句话 |
| `meta` | 底部小字，如「认知 · 科普」 |

```json
{"type":"title","say":"…","params":{"kicker":"CODE ANIMATION","title":"为什么动画更好懂","sub":"双通道编码，一次讲清","meta":"认知 · 科普"}}
```

### 3.2 `bullets` · 要点列表
用于"原因有三条""几个判断标准"。条目**依次**出现。

| 参数 | 说明 |
|---|---|
| `title` | 页标题 |
| `items` | 3–4 条，每条 ≤ 18 字；支持 `<em>关键词</em>` 高亮 |

```json
{"type":"bullets","say":"…","params":{"title":"为什么更有效","items":["视觉和听觉，两条通道<em>并行</em>","抽象的词，被换成<em>看得见</em>的东西"]}}
```

### 3.3 `stat` · 大数字
一个数字撑满一屏，数字会从 0 滚上去。

| 参数 | 说明 |
|---|---|
| `value` | 数字，或任意短词 |
| `decimals` | 小数位，默认自动 |
| `unit` | 单位，如「倍」「%」 |
| `label` | 这个数字是什么 |
| `note` | 脚注，**数据来源必须写这里** |

> ⚠️ 数字必须是真数据。没有出处就写「数量级示意」，或者别用这个镜头。

### 3.4 `quote` · 金句
一屏一句话，居中。用于引用、结论、转折。

| 参数 | 说明 |
|---|---|
| `text` | 支持 `<br>` 换行 |
| `by` | 出处 |

### 3.5 `image` · 图片
一张图铺满，缓慢推近（Ken Burns），可带说明条。

| 参数 | 说明 |
|---|---|
| `src` | `assets/xxx.png`，相对项目目录 |
| `caption` | 左下角说明条，可空 |
| `kenburns` | `in`（默认）/ `left` / `right` |
| `zoom` | 整体放大倍数，默认 1 |

### 3.6 `video` · 视频片段
播放一段 B-roll。渲染时逐帧 seek，所以**确定性**。

| 参数 | 说明 |
|---|---|
| `src` | `assets/xxx.mp4` |
| `start` | 从第几秒开始播 |
| `loop` | 默认 true，片段比镜头短时循环 |
| `zoom` | 放大倍数，用来裁掉原片的水印/字幕 |

> ⚠️ 用别人的素材时，剪掉自带的字幕条——会和你的字幕打架。优先用 `zoom` 裁掉底部。

### 3.7 `compare` · 左右对比
左边 vs 右边，逐条出现。**最有用的一种镜头**：讲原理、讲改变、讲误解，几乎都能用。

| 参数 | 说明 |
|---|---|
| `title` | 页标题 |
| `left.label` / `right.label` | 两栏标题 |
| `left.items` / `right.items` | 各 2–4 条 |

```json
{"type":"compare","params":{"title":"一条通道，还是两条",
  "left":{"label":"只有文字","items":["符号→先在脑中翻译","翻译失败就断片"]},
  "right":{"label":"画面 + 讲解","items":["直接看到结构","边看边听"]}}}
```

### 3.8 `flow` · 流程
横向步骤条 + 箭头，依次点亮。

| 参数 | 说明 |
|---|---|
| `title` | 页标题 |
| `steps` | 3–5 步，每步 ≤ 6 字 |
| `skip` | 要「划掉」的步骤下标数组，如 `[1]` |
| `note` | 下方一行小字 |

> `skip` 是这个镜头的灵魂：讲"省掉了哪一步""绕过了哪个环节"时，把那一步划掉，观众一眼就懂。

### 3.9 `bars` · 柱状图
数据对比，柱子长出来。

| 参数 | 说明 |
|---|---|
| `title` | 页标题 |
| `data` | `[{name, value}]`，3–6 条 |
| `unit` | 数值后缀，如「%」 |
| `max` | 纵轴上限，默认取最大值 |

> 同样：**数据必须有出处**，没出处的数据不要做成柱状图，那是在造谣。

### 3.10 `code` · 代码
带窗口装饰的代码块，逐行高亮。

| 参数 | 说明 |
|---|---|
| `title` | 页标题 |
| `lang` | 右上角语言名，如 `Python` |
| `code` | 多行字符串 |
| `highlight` | 要高亮的行号数组；不给则逐行点亮 |

### 3.11 `person` · 人物卡
提到一个人时用。左边照片，右边姓名 / 身份 / 一句说明。

| 参数 | 说明 |
|---|---|
| `name` | 姓名 |
| `role` | 身份，如「NVIDIA 创始人 & CEO」 |
| `note` | 一句说明，讲他在这一段里的作用 |
| `photo` | 可选。没有就渲染成首字母文字卡 |
| `credit` | 照片署名，**用了照片必须填** |

```json
{"type":"person","params":{"name":"黄仁勋","role":"NVIDIA 创始人 & CEO",
  "note":"他把显卡卖成了 AI 时代的硬通货。","photo":"assets/jensen.jpg",
  "credit":"Photo: Prime Minister's Office / GODL-India · Wikimedia Commons"}}
```

### 3.12 `brand` · 品牌卡
提到一个公司 / 产品时用。默认是**文字 wordmark**，不抓 logo。

| 参数 | 说明 |
|---|---|
| `name` | 品牌名，如 `NVIDIA` |
| `color` | 品牌色，如 `#76b900` |
| `note` | 一句话，讲它在这段里的角色 |
| `logo` | 可选，仅当用户提供素材时用 |

> 为什么不自动抓 logo：实测从 Commons 搜「Nvidia logo」拿到的是**总部大楼照片**。
> 抓错的图比没有图更丢人，所以默认走文字卡。

## 4. 编译：括号 → storyboard.json

这是 agent 唯一需要动脑的环节，也是全片质量的分水岭。

### 4.1 决策顺序

对每个括号，按顺序问：

1. **这句话里有东西在动吗？** 没有 → 用 `quote` 或 `title`，或者干脆不加镜头（把它并到下一镜）。
2. **是一个数 / 一个比例吗？** → `stat` 或 `bars`
3. **是"两种东西不一样"吗？** → `compare`
4. **是"几个步骤 / 省掉哪一步"吗？** → `flow`
5. **是"一堆并列的要点"吗？** → `bullets`
6. **提到了一个人？** → `person`（照片要确认过）
7. **提到了一个公司 / 产品？** → `brand`
8. **有现成的图 / 视频吗？** → `image` / `video`
9. **都不是** → 说明这个括号没想清楚，**回去改稿**。

### 4.2 常见括号写法对照表

| 括号里通常这么写 | 用哪个 | 备注 |
|---|---|---|
| 片名卡 / 开场 / 标题浮现 | `title` | 首尾各一个 |
| 三条原因 / 几个要点 / 罗列 | `bullets` | 3–4 条，别超过 4 |
| 大数字 / 两倍 / 90% / 翻一倍 | `stat` | 数字要真 |
| 金句 / 引用 / 他说 | `quote` | 不配图 |
| 一张图 / 截图 / 照片 / 示意图 | `image` | 图要干净 |
| 放一段视频 / 片段 / B-roll | `video` | 裁掉原字幕 |
| 左右对比 / 以前 vs 现在 / 误解和真相 | `compare` | 最好用 |
| 流程 / 三步 / A→B→C / 省掉了哪一步 | `flow` | 用 `skip` 划掉 |
| 柱状图 / 数据对比 / 占比 | `bars` | 数据要真 |
| 代码 / 关键那几行 | `code` | 一屏 ≤ 12 行 |

### 4.3 反例：括号写了抽象词怎么办

> 口播：「大脑的工作记忆容量有限。」
> 括号：（画面：展示工作记忆的容量限制）← **画不出来**

三种解法，选一个：

1. **换成具体的东西**：`compare` 左边"一次只能想 3 件事"，右边"画面帮你挂住 3 件"。
2. **改成不配图**：这句是结论，用 `title` 上大字，让观众读。
3. **改稿**：把这句话改写成带动作的——「你同时记三个数还行，记五个就开始丢。」

**不要**为了这一句硬造一个抽象图形。那是配图。

## 6. 质量检查（交付前必须过）

### 6.1 遮住字幕，问三句

任取五个镜头，遮住字幕和所有小字，只留画面，问自己：

1. **这是什么？**（要用日常的词回答，不能是"一个抽象概念"）
2. **它在干什么？**（一个动词）
3. **我看明白了什么？**（一句话，说得出因果）

**答得含糊的镜头，就是没做好。** 回去改，不是回去加字幕。

### 6.2 五条硬指标

| 检查项 | 标准 |
|---|---|
| 镜头时长 | 单镜 3–9 秒；超过 10 秒且画面不动，拆 |
| 字幕 | 一屏一行，≤ 24 字，出现 0.2 秒内屏上要有动作 |
| 画面主体 | 任一时刻只有一个主体在动 |
| 图 / 视频 | 没有和字幕打架的烧录文字；没有水印 |
| 数据 | 每个数字有出处，没出处的标「示意」 |

### 6.3 常见毛病对照

| 症状 | 病因 | 药 |
|---|---|---|
| 看着像 PPT | 全是 `bullets` 和 `title` | 中间插 `compare` / `flow` / `bars` |
| 看着很忙但没记住 | 一镜塞了三件事 | 拆 |
| 抽象、听不懂 | 抽象词硬配抽象图 | 换具体形象，或只上字 |
| 节奏平 | 每镜一样长、一样重 | 长短交替：短镜 3 秒，重点镜 8 秒 |
| 字幕和图打架 | 素材自带字幕条 | `zoom` 裁掉，或换素材 |

## 7. 扩展

### 7.1 加一种新镜头

1. 在 `kit/scenes.js` 写 `buildXxx(s)`，返回 `{el, render(t)}`；
   **`render(t)` 必须是 t 的纯函数**，不许用 `Date.now()` / `Math.random()`。
2. 注册进 `BUILDERS`。
3. 在 `kit/style.css` 加样式（用 `:root` 里的变量，别写死颜色）。
4. 在本文件第 3 节补一条说明。

### 7.2 换主题

只改 `kit/style.css` 的 `:root`：6 个颜色 + 4 个字号 + `--pad`。**不要逐条改**。

### 7.3 换音色

`storyboard.json` 的 `meta.voice`：

| 音色 | 感觉 | 适合 |
|---|---|---|
| `zh-CN-YunxiNeural` | 男·青年·松弛 | 科普、碎碎念（默认） |
| `zh-CN-XiaoxiaoNeural` | 女·温柔 | 教学、知识分享 |
| `zh-CN-YunyangNeural` | 男·播音腔 | 严肃科普、新闻式 |
| `zh-CN-YunjianNeural` | 男·浑厚 | 纪录片旁白 |

`meta.rate` 控制语速，默认 `+8%`。实测同一段话：

| rate | 时长 | 相对 -4% |
|---|---|---|
| `-4%` | 8.88s | — |
| `+0%` | 8.54s | 快 4% |
| `+4%` | 8.21s | 快 8% |
| **`+8%`** | **7.90s** | **快 12%**（默认） |
| `+12%` | 7.63s | 快 16% |

想临时改语速不用动 JSON：

```bash
node build.mjs projects/xx --rate +12%
```

调完记得把 `storyboard.json` 的 `meta.rate` 一起改，否则下次跑又变回去。

### 7.4 批量做一整个系列

一个系列 = 一个目录，多个 `storyboard.json`：

```bash
for p in projects/series-01/*/; do node build.mjs "$p"; done
```

配音有缓存（按文本 hash），改一镜只重跑那一镜的 TTS。

### 7.5 素材来源与署名

| 素材 | 从哪来 | 规矩 |
|---|---|---|
| 人物照片 | `node studio/fetch-media.mjs "姓名" assets/x.jpg` → Wikimedia Commons | **下载后必须亲眼看一遍**，确认是本人；确认不了就删掉用文字卡 |
| 品牌 logo | 不自动抓 | 用 `brand` 文字卡；用户给了素材才用 |
| 图片 / 视频 | 用户给 | 放在 `assets/`，路径写相对项目目录 |
| 数据 | 用户给 / 公开来源 | 没出处的**不许**做成 `stat` / `bars` |

用了 Commons 的图，`credit` 字段必须填（作者 + 协议），成片里会显示在右下角。

## 8. 已知的坑

| 坑 | 说明 |
|---|---|
| **edge-tts 连不上** | 接口偶发 connection reset，`tts.py` 里带 24 次快速重试，实在不行退回系统 `say`（音色会明显变差，注意检查） |
| **字幕闪一下** | 字幕窗口跟着镜头走，镜头切换有 0.2 秒淡出；句子太碎就会闪，合并短句 |
| **视频素材自带字幕** | 渲染出来两层字叠在一起，用 `zoom` 裁掉底部 |
| **图片比例不对** | `image` 用 `object-fit:cover`，会裁边；重要内容别放边上 |
| **旁白念错英文词** | TTS 读 `transform` 这类词口音可能怪，必要时在稿子里改写（"transform 这个属性"→"transform，这个属性"） |
| **一镜太长** | 超过 12 秒观众会走神，拆成两镜，中间换个画面 |

## 9. 给 agent 的执行协议

接到「把这段文字做成视频」时，按这个顺序走，**每一步都有验收标准，没过不要往下走**。

| 步 | 做什么 | 过关标准 |
|---|---|---|
| 0 | **校对**用户原文（不是润色） | 只改语病 / 错别字 / 事实错误；口头禅一个不动；改动逐条列出，没改就写「未改动」 |
| 1 | 读稿，逐句标出「屏上主体」 | 每句都能说出一个具体的、看得见的东西；说不出的句子标红 |
| 2 | 处理标红的句子 | 改写 / 换形象 / 合并；**不许硬配抽象图** |
| 3 | 取素材（有人物/品牌才做） | 照片亲眼确认过；确认不了用文字卡 |
| 4 | 编译 `storyboard.json` | 每镜的类型选得对（第 4 节决策树），参数填全 |
| 5 | `--timeline` 对轴 | 每镜 3–9 秒；没有超过 12 秒的 |
| 6 | `--stills` 审画面 | 至少看 5 个时刻，过第 6.1 节三问 |
| 7 | 全片渲染 | 无报错，时长与稿子误差 < 1 秒 |
| 8 | 自检 | 第 6.2 节五条全过 |
| 9 | 交付 | 给成片 + 海报帧 + 一份「本次没做到的地方」 |

**第 6 步是分水岭。** 大部分失败是因为跳过它、直接整片渲染然后交片。
